# AGENTS.md

This file provides guidance to coding agents working with code in this repository. `CLAUDE.md` imports it, so keep the guidance here.

## About This Repo

Personal website and blog for Andy Waite, built with [Astro](https://astro.build/) (static output) and deployed to Cloudflare Workers (static assets) via Workers Builds. The site was migrated from Jekyll; the original Jekyll URLs still resolve.

## Commands

```bash
# Install dependencies
npm install

# Serve locally with hot reload (drafts are included)
npm run dev

# Type-check and build the static site to dist/
npm run build

# Preview the production build
npm run preview

# Preview with Cloudflare's asset routing (see "Deployment")
npx wrangler dev
```

## Content Structure

- `_posts/` — Blog posts as Markdown, named `YYYY-MM-DD-slug.md`. Kept in Jekyll's layout on purpose.
- `src/content/pages/` — Standalone pages (`about.md`, `contact.md`, `work.md`).
- `src/pages/` — Routes. `[...path].astro` renders posts; `about/`, `contact/`, and `work/` render the standalone pages.
- `src/lib/posts.ts` — Post date/slug/category helpers, draft filtering, and canonical URL generation.
- `src/layouts/` — `BlogPost.astro`, `Page.astro`, and `MarkdownPage.astro`.
- `src/styles/global.css` — Global styles (based on the Astro blog starter), plus component-scoped styles.
- `public/assets/images/` — Images served from `/assets/images/...`.
- `public/robots.txt` — Crawler config. There is deliberately no `CNAME` file; the custom domain is configured on the Cloudflare Pages project.

## Posts and URLs

- Frontmatter supports `title`, `date`, `categories`, `published`, `draft`, and `reddit_url`. Unknown keys are ignored.
- If `date` is omitted, the date is read from the filename prefix.
- Canonical post URLs are generated by `postHref()` in `src/lib/posts.ts`: `/:categories/:year/:month/:day/:slug`. Categories are space-separated in frontmatter, as in Jekyll.
- Workers static assets serve `dist/**/<slug>.html` at the extension-less path and permanently redirect (308) requests for the `.html` form, per `html_handling` in `wrangler.jsonc`. So the Jekyll URLs such as `/rspec/bdd/testing/2013/02/21/playing-with-rspec-fire.html` still resolve, but they redirect to the canonical URL. That is why every internal link, the sitemap, and the feed use the extension-less form. (`html_handling: "none"` would serve the `.html` URLs verbatim, but then directory pages such as `/about/` and `/` stop resolving without `_redirects` rules, so it is not worth it.)
- `build.format: 'preserve'` in `astro.config.mjs` keeps the Jekyll file layout: posts are written as `.html` files and pages such as `/about/` stay directories. Do not switch it to `file` or `directory` without checking URLs on the deployed site.
- Do **not** rename post files to `.markdown`; the content loader only picks up `.md` (and `.mdx`).

## Drafts

- `published: false` (Jekyll) and `draft: true` (Astro) both hide a post from production builds.
- Drafts are rendered at their canonical (extension-less) URL when running `npm run dev`, so you can preview them, but they are never listed on the homepage and never reach `dist/` in a production build.

## Creating New Posts

1. Run `date` to verify the current date before naming the file.
2. Create the file as `_posts/YYYY-MM-DD-<slug>.md`, where `<slug>` is lowercase and hyphenated. Do not rename existing files.
3. Add front matter at the top of the file:

   ```yaml
   ---
   layout: post
   title: "Post title"
   date: YYYY-MM-DD
   published: false
   ---
   ```

   `categories` (space-separated, as in Jekyll) and `reddit_url` are optional.
4. Always start with `published: false`. Drafts preview in `npm run dev` but are excluded from the homepage and from production builds.
5. Run `npm run dev` and open the post at its canonical URL to preview it. The URL is `/<categories>/<year>/<month>/<day>/<slug>`, with the categories segment omitted if there are none — e.g. `/2026/11/10/llm-chat`. In `dist/` it is written as `llm-chat.html`.
6. When the post is ready, set `published: true` to publish it.

The target audience is senior/staff developers — assume deep technical knowledge and avoid over-explaining fundamentals.

## Generated Feeds and Metadata

- `/feed.xml` — RSS feed (latest 10 posts), generated by `src/pages/feed.xml.ts`. `trailingSlash: false` is set so item links stay at the extension-less post URLs.
- `/sitemap.xml` — Hand-written sitemap endpoint (`src/pages/sitemap.xml.ts`) so the canonical post URLs are listed exactly.
- `/resume` — Redirect to the Google Doc (`src/pages/resume.astro`, written to `resume.html`).
- `/404.html` — `src/pages/404.astro`, served for unmatched paths via `not_found_handling: "404-page"` in `wrangler.jsonc`.

## Deployment

Cloudflare Workers builds and deploys from this repository via Workers Builds (GitHub integration); there is no deployment workflow in the repo.

- Build command `npm run build`, deploy command `npx wrangler deploy`, production branch `main`. Other branches and pull requests get preview deployments.
- `wrangler.jsonc` uploads `dist` as static assets. There is deliberately no `@astrojs/cloudflare` adapter and no Worker script: the site is fully static, so the adapter's `dist/client` + `dist/server` split and its IMAGES/SESSION bindings would add nothing. Do not let `astro add cloudflare` run here.
- Worker name `andyw8-github-io` (from the repo name) must match the project, otherwise Workers Builds warns about the mismatch and tries to open a pull request. The custom domain `andywaite.com` is attached to the Worker, along with `www.andywaite.com`.
- `public/_headers` sets an immutable cache for `/_astro/*`.
- The Workers build image uses Node 24, which satisfies the `engines` field in `package.json`.
- GitHub Pages was the previous host. `public/CNAME` and `.github/workflows/deploy.yml` were removed for that reason; disable Pages in the repo settings so the old deployment stops serving.
- `npm run preview` uses Astro's server, which does not apply Cloudflare's asset routing (`/foo.html` is served rather than redirected). Use `npm run build && npx wrangler dev` to check how the deployed site will behave.

## About This Repo

Personal website and blog for Andy Waite, built with [Astro](https://astro.build/) (static output) and deployed to GitHub Pages via GitHub Actions. The site was migrated from Jekyll; legacy URLs are preserved intentionally.

## Commands

```bash
# Install dependencies
npm install

# Serve locally with hot reload (drafts are included)
npm run dev

# Type-check and build the static site to dist/
npm run build

# Preview the production build
npm run preview
```

## Content Structure

- `_posts/` — Blog posts as Markdown, named `YYYY-MM-DD-slug.md`. Kept in Jekyll's layout on purpose.
- `src/content/pages/` — Standalone pages (`about.md`, `contact.md`, `work.md`).
- `src/pages/` — Routes. `[...path].astro` renders posts; `about/`, `contact/`, and `work/` render the standalone pages.
- `src/lib/posts.ts` — Post date/slug/category helpers, draft filtering, and legacy URL generation.
- `src/layouts/` — `BlogPost.astro`, `Page.astro`, and `MarkdownPage.astro`.
- `src/styles/global.css` — Global styles (based on the Astro blog starter), plus component-scoped styles.
- `public/assets/images/` — Images served from `/assets/images/...`.
- `public/CNAME`, `public/robots.txt` — GitHub Pages custom domain and crawler config.

## Posts and URLs

- Frontmatter supports `title`, `date`, `categories`, `published`, `draft`, and `reddit_url`. Unknown keys are ignored.
- If `date` is omitted, the date is read from the filename prefix.
- Legacy permalinks are generated by `postHref()` in `src/lib/posts.ts`: `/:categories/:year/:month/:day/:slug.html`. Categories are space-separated in frontmatter, as in Jekyll.
- `build.format: 'preserve'` in `astro.config.mjs` is what makes posts end in `.html` while pages such as `/about/` stay directories. Do not switch it to `file` or `directory` without checking every legacy URL.
- Do **not** rename post files to `.markdown`; the content loader only picks up `.md` (and `.mdx`).

## Drafts

- `published: false` (Jekyll) and `draft: true` (Astro) both hide a post from production builds.
- Drafts are rendered at their `.html` URL when running `npm run dev`, so you can preview them, but they are never listed on the homepage and never reach `dist/` in a production build.

## Creating New Posts

When creating a new post:

1. Run `date` to verify the current date before naming the file.
2. Name the file `YYYY-MM-DD-slug.md` under `_posts/`.
3. Always set `published: false` in the front matter initially.
4. Run `npm run dev` and open the post at its `.html` URL to preview it.

The target audience is senior/staff developers — assume deep technical knowledge and avoid over-explaining fundamentals.

## Generated Feeds and Metadata

- `/feed.xml` — RSS feed (latest 10 posts), generated by `src/pages/feed.xml.ts`.
- `/sitemap.xml` — Hand-written sitemap endpoint (`src/pages/sitemap.xml.ts`) so legacy `.html` URLs are listed exactly.
- `/resume.html` — Redirect to the Google Doc (`src/pages/resume.astro`).
- `/404.html` — `src/pages/404.astro`.

## Deployment

- `.github/workflows/deploy.yml` builds with `withastro/action` and deploys with `actions/deploy-pages`.
- The repository's Pages settings must use **GitHub Actions** as the source (not "Deploy from a branch"). The custom domain is `andywaite.com`, carried in `public/CNAME`.
- Builds run on Node 24 in CI (also required: Node >= 22.23.4 locally).

## CI

Dependabot PRs for non-major updates are auto-approved and auto-merged via `.github/workflows/dependabot_automerge.yml`.
